## What is New in v0.3.3-alpha.1

### 1. True cutout fullscreen
- `Theme.PortSotC.Fullscreen` now declares `android:windowLayoutInDisplayCutoutMode=shortEdges` and transparent status/navigation bars, so all fullscreen activities span the cutout edge instead of gaining an inset.
- `GameNativeActivity` re-applies immersive, cutout-spanning window flags on focus gain after transient system bars are dismissed. `GameActivity` already did this.
- `smallestScreenSize` was added to the `configChanges` of both gameplay activities so a display-size change does not restart the session.

### 2. Host presentation hardening (source-level)
- The diagnostics fullscreen blit now disables `GL_CULL_FACE` in `RenderTarget` (bind and present), `HdShaderPipeline::present` and the engine direct path. Stale guest cull state could otherwise discard the fullscreen triangle and leave a black surface.
- `HdShaderPipeline::configureSampler` only enables mipmapped minification when the source is power-of-two, the context is ES 3, or `GL_OES_texture_npot` is advertised; `glGenerateMipmap` is skipped otherwise. The GLES2 floor (D21) is unchanged. This removes a second black-screen risk that affected `BALANCED`/`ULTRA` (anisotropy >1) on ES2 drivers without NPOT mipmap support.
- No ES3-only rewrite and no `SotcSafePresenter` class: the existing single-owner `Engine`/`RenderTarget`/`HdShaderPipeline` pipeline and the runner's own presentation path are preserved (D21/D23/D31/D34).

### 3. Console-grade UI polish
- Import actions are ordered `SELECT ISO IMAGE` → `START IMPORT` → `CLOSE`, with a localized `import_close` string replacing a hardcoded label.
- Launcher bottom navigation tiles place the matte vector icon above a non-wrapping `IMPORT` / `SETTINGS` / `CONTROLS` label and use a taller 64.dp hit target.
- Controller settings replaces the raw monospace key dump with structured, bordered PlayStation keycap rows beside friendly keyboard key names. A `R1 GRIP MODE` selector exposes Latch / Hold / Hybrid, mapped to the existing Claw / Shoulder / Bridge settings (D34).

### 4. Preserved behavior
- The packaged ARM64 runner is **unchanged** from `v0.3.2-alpha.1` (patch 0012). No new runner patch was needed; no celosia or runner source was modified.
- `UNLIMITED` remains the default and still maps to `eglSwapInterval(0)`; `60 FPS` and `30 FPS` map to `1` and `2`. The EE/VBlank simulation clock remains 1.0x with the existing 50 ms `SOTC_SIM_MAX_DT_MS` clamp. The 33.3 ms clamp from the master specification was rejected because it would discard real wall-clock time after a 40-50 ms stall and slow the guest (D34).

## Technical Constraints & Honest Status

- **No physical device evidence:** no boot, rendering, audio, gameplay, touch-ergonomics, fullscreen, preset or frame-rate claim has been verified on hardware. All gates below are host-side, compile-time and APK-structure checks.
- The host x86 smoke asserts parsing, pacing, adaptive decisions and HD-shader telemetry. It still does **not** assert non-black rendered pixels or fullscreen viewport dimensions; no rendering claim is made from it (D33/D34).
- **Estimate unchanged:** the 5-7 FPS recompiled-guest bottleneck (Known Issue #13, Blocker B6) still requires device profiling. No performance improvement may be claimed.
- **Design references:** the PNG files under `docs/design/` were implemented from their written specification; they were not visually inspected by the agent.
- Pre-existing warnings remain (unused `onHdSettings` parameter, deprecated `onBackPressed`, Gradle CXX5304 SDK XML notices); the gate still succeeds.
