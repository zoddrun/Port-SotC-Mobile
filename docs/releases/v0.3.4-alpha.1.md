## What is New in v0.3.4-alpha.1

This is a targeted follow-up to `v0.3.3-alpha.1`. It adds real, app-private disc inspection, local setup milestones, a memory-card backup vault and an isolated native diagnostics cache. The active gameplay path, the patch-0012 runner, the patch chain and the alignment contract are **unchanged** (D35).

### 1. Real disc inspector and BOOT2 identifier
- `DiscInspector` reads the app-private imported ISO with the existing `Iso9660Image`, `DiscValidator` and `Ps2Elf` code. It reports the whole-image SHA-256, volume/system identifiers, sector counts, boot path and name, ELF header facts and module summaries.
- The BOOT2 identifier is MD5 over the primary executable name from `SYSTEM.CNF` followed by the executable bytes. `SystemCnf.primaryExecutableNameFromBootPath` preserves PS2 path separators and stops at the ISO version suffix.
- The inspector is reachable from Settings → Disc Inspector and from a new launcher tool button. An inspection durably records the serial, boot name, BOOT2 MD5 and image SHA-256 in app-private preferences.
- This identifier is computed locally for setup evidence only. **No achievement service is contacted and no RetroAchievements claim is made.**

### 2. Original local milestones
- A `LocalAchievementLedger` evaluates seven original setup milestones: supported disc imported, image digest verified, BOOT2 identified, runtime files prepared, native runtime packaged, memory-card backup created and native report cached.
- Conditions come from real files, digests and packaged-library checks. Milestones are shown under Settings → Achievements and from the launcher tool button; the local unlock record can be reset without touching game data.
- These are **not** Shadow of the Colossus trophies, RetroAchievements, or evidence of gameplay, rendering, audio or a save on a physical device.

### 3. Memory-card vault
- `MemoryCardVault` creates versioned ZIP snapshots of the files the recompiled runtime writes under `disc/mc0`, lists them with real metadata, deletes them, and restores them into a staged directory before atomically replacing the live directory. The pre-restore directory is retained for recovery.
- Archive entries and backup names are checked for path traversal. An empty memory-card directory is rejected so a backup never looks like progress before the runtime has written anything.
- `DiscTreeExtractor` now preserves existing `mc0` files when a new image digest forces re-extraction. This is a file-level preservation step; the app does **not** parse or validate PlayStation 2 memory-card structures and does not claim save compatibility.

### 4. Isolated native diagnostics cache
- `NativeDiagnosticsCache` stores diagnostics-only `NativeCore`/GPU probe reports in app-private storage under `files/diagnostics`. It is exposed under Settings → Advanced with refresh/clear actions.
- The cache never feeds gameplay configuration or settings. `GameActivity` and native `Engine` remain diagnostics only; `GameNativeActivity` plus `libps2EntryRunner.so` remain the active gameplay path.

### 5. Preserved behavior
- No C++/CMake/JNI source was changed. No runner patch, celosia change, patch-chain change or `scripts/apply-patches.sh` change was made.
- `SCUS-97472` remains the only supported serial and `KNOWN_UNVERIFIED_SERIAL` still rejects the other eight recognized releases.
- No emulator backend, game asset, ISO, BIOS, ROM or copyrighted content was added to the repository or the APK.

## Technical Constraints & Honest Status

- **No physical device evidence:** no boot, rendering, audio, gameplay, touch-ergonomics, fullscreen, preset, pacing or save-loading claim has been verified on hardware. All gates below are JVM, compile-time, host-smoke and APK-structure checks.
- The host x86 smoke asserts parsing, pacing, adaptive decisions and HD-shader telemetry. It still does **not** assert non-black rendered pixels or fullscreen viewport dimensions; no rendering claim is made from it (D33/D34).
- Disc inspection only reads an already imported, app-private image. It does not validate the developer's original disc, contact a network service or prove that the runtime can load the executable.
- The vault's file-level backup does not parse PS2 memory-card formats. A successful backup or restore proves only that app-private files were copied correctly.
- Local milestones are setup evidence, not gameplay achievements. The BOOT2 digest follows a public identification rule but is not asserted to be registered anywhere.
- Re-extraction preserves `mc0` files by copying them into the staged tree; it is not a PS2 save-conversion or compatibility feature.
- **Estimate unchanged:** the 5-7 FPS recompiled-guest bottleneck (Known Issue #13, Blocker B6) still requires device profiling. No performance improvement may be claimed.
- Pre-existing warnings remain (unused `onHdSettings` parameter, deprecated `onBackPressed`, Gradle CXX5304 SDK XML notices and 116 lint `HardcodedText`/resource warnings). None was introduced or hidden by this follow-up; the gate still succeeds.
