> **This is not a playable port yet.** The statically recompiled ARM64 game runtime is now packaged and passes every no-device gate, but no ARM64 Android device has loaded it. Importing a supported disc image does not make the game playable in this preview. No gameplay, rendering, audio or lifecycle claim is made.

## What this release is

The second public development preview of **Shadow of the Colossus Mobile**, a native Android port of the original PlayStation 2 release through Celosia/PS2Recomp **static recompilation** (not emulation). It contains the Android host application **and**, for the first time, a packaged ARM64 recompiled runtime (`libps2EntryRunner.so`). The runtime is built, statically verified and wired to the settings, but has never run on a phone.

It does **not** contain game data, ISO images, BIOS files, or any copyrighted game content. Players import their own legally obtained disc image through the Storage Access Framework.

## What is new since v0.1.0-alpha.1

- **Packaged ARM64 recompiled runtime** built from the pinned celosia `f8c269e` with the full Android patch series (0001-0009). `verify-runner.sh` confirms ELF64 AArch64 `ET_DYN`, 16 KB LOAD alignment, `ANativeActivity_onCreate` and the touch overlay entry points, no `libc++_shared.so` dependency, and `libandroid.so` glue.
- **Runner-owned pacing (patch 0009):** the app publishes `SOTC_FRAME_LIMIT` (0/30/60, presentation only), `SOTC_ADAPTIVE_RESOLUTION`, `SOTC_RENDER_SCALE`, `SOTC_PERF_OVERLAY` and `PS2X_STATS` as process environment before the NativeActivity loads. The runner owns its adaptive scale and raylib `SetTargetFPS` cap; a five-second `[pace]` record reports the accepted values. `SOTC_CAP20` is deliberately not used because it changes guest timing.
- **Capability-based GPU tiers:** the native detector now probes EGL identity/extensions, GL limits, advertised timer/fence flags, and shader/FBO/colour/depth/render-to-texture self-tests. Tiers are derived from passing probes, never from a GPU vendor string. Advertised extensions are labelled separately from measured results.
- **16 KB page-size packaging fix:** both native libraries now use the static C++ runtime, removing the 4 KB-aligned `libc++_shared.so`. A new APK-wide gate (`verify-apk.py`) checks every packaged `.so` for ELF class, ABI, type, 16 KB LOAD/ZIP alignment, dependencies and BuildID.
- **Audited upstream research:** `UPSTREAM_REPO_AUDIT.md`, `GPU_COMPATIBILITY_MATRIX.md`, `PERFORMANCE_ARCHITECTURE.md` and `ANDROID_RUNTIME_INTEGRATION.md` record the architecture, rationale and no-phone evidence ladder.
- Honest settings captions: next-session-only behaviour, runner scale floor `0.5`, and host-only settings are stated in the UI; no misleading full-game ES 2 claim.

## What is not available yet

- **Adaptive resolution is a no-op with the default settings.** Patch 0009's adaptive scale needs the perf-statistics path (`SOTC_PERF_OVERLAY`), which the app maps to "Show statistics" (default off), while adaptive resolution defaults on. It changes scale only when statistics are enabled, and even then has no device evidence. The frame limit (0/30/60) is host-smoke-tested independently. See `../agent/KNOWN_ISSUES.md` item 8.
- No ARM64 device evidence: first boot, window creation, real game rendering, game audio, touch overlay in gameplay, gamepad merge, lifecycle, saves and thermals are all unverified.
- No verified ES 3 runtime path or on-device frame limiter (the API 28 emulator is GLES 2.0 / SwiftShader and cannot load the ARM64 runner).
- Thermal policy remains host-only; no runner thermal input is implemented.
- GPU self-tests use synthetic shaders and small targets; a passing tier is a launcher diagnostic, not full-game compatibility.
- Debug-signed build; not a production release.

## Installation

1. Download the APK asset from the release page.
2. Allow installation from unknown apps if prompted.
3. Install and open **Port SotC Mobile**.
4. Optionally import a legally obtained `SCUS-97472` ISO through **Import Game** and use **Prepare Game Data**; Play is enabled only when the runner and extracted tree are present. This does not enable gameplay on unsupported hardware.
