## What is New in v0.3.2-alpha.1

### 1. Presentation and pacing fixes
- **Black screen on `BATTERY` / `BALANCED`:** the HD present path now checks `GL_FRAMEBUFFER_COMPLETE`, rebinds framebuffer 0, restores a full-surface `glViewport`, and disables scissor and depth state before the final blit. An invalid or failed HD shader program falls back to the direct blit instead of leaving a black surface.
- **Frozen `ULTRA` / `0 FPS`:** frame statistics are sampled after presentation instead of before it, so a slow draw no longer leaves the FPS counter at zero. The EE/VBlank simulation clock follows real time at 1.0x and discards stalls longer than `SOTC_SIM_MAX_DT_MS` (50 ms default) instead of replaying them.
- **True `UNLIMITED` FPS:** `UNLIMITED` is the default and uses `eglSwapInterval(0)`; `60 FPS` and `30 FPS` map to `eglSwapInterval(1)` and `2`. The option is exposed in Settings and quick settings as `UNLIMITED`, `60 FPS`, `30 FPS`.
- **GS texture cache:** the active Android GS backend (`gs_cpu_backend.cpp` + `gs_hw_backend.cpp`) keys decoded texels by a 64-bit FNV-1a source hash (prime `1099511628211`) plus the GS CLUT signature and reuses GL storage with `glTexSubImage2D`. The same CLUT signature and `rgbaFnv1a` dedup were added to the Apple/Vita native GL renderer, which reports `cached` and `reused` counters; that renderer is platform-guarded and is not the Android presentation path.
- **No blocking readback in the render loop:** depth/stencil are discarded on the default framebuffer before swap via `eglGetProcAddress("glInvalidateFramebuffer")`; no `glFinish()` or `glReadPixels()` was added to the presentation path. The remaining `glFinish()` calls are guarded by Vita-only build flags.

### 2. Fullscreen presentation
- `GameActivity` applies immersive, cutout-spanning window flags in both `onCreate()` and `onWindowFocusChanged()`.
- Full widescreen viewport is the default; 4:3 and integer modes remain selectable in the player menu.
- Horizontal FOV is aspect-corrected in widescreen mode through `native_renderer::setAspectClipScale()`.
- The green FPS/debug overlay is hidden by default.

### 3. Vector touch HUD
- Face buttons are drawn as geometric `△ ○ ✕ □` glyphs; R1/grip uses a double ring.
- The left stick is a floating stick with N/S/E/W ticks; camera control is a right-half drag with no static right-stick circle.
- L1/L2/R2 are pill-shaped controls, weapon selection uses `<` / `>` pills, and `•••` opens quick settings.
- The runner HUD auto-hides while a gamepad is active. Haptic feedback remains implemented only in the host `TouchControllerView`; the runner has no JNI haptics bridge.

### 4. Launcher and diagnostics polish
- 20.dp vector navigation icons and non-wrapping `IMPORT`, `SETTINGS`, `CONTROLS` labels.
- Atmospheric hero header on the launcher home screen.
- Virtual/kernel gamepad devices are filtered out of the controller list.
- The native logger flushes every boot and error line (`setvbuf` line buffering plus explicit `fflush`).

## Technical Constraints & Honest Status

- **No physical device evidence:** no boot, rendering, audio, gameplay, touch-ergonomics, fullscreen, preset or frame-rate claim has been verified on hardware. All gates below are host-side, compile-time and APK-structure checks.
- **Estimate unchanged:** the 5-7 FPS recompiled-guest bottleneck (Known Issue #13, Blocker B6) still requires device profiling. This release adds a texture cache and presentation/pacing fixes that target contributing factors, but none of them has been measured on ARM64 hardware.
- **Design references:** the PNG files under `docs/design/` were implemented from their written specification; they were not visually inspected by the agent.
