## What Works Today (verified)

- Android host app builds (Gradle wrapper, arm64-v8a + x86_64) and has 105 passing unit tests; lint and `assembleDebug` pass. The `v0.2.0-alpha.1` debug APK is 112,640,655 bytes, SHA-256 `F7A70D120B8646618E93EF77DECBDEF0426D37D703CBBD04E96955F2826767D8` (version 0.2.0, code 2); it contains `lib/arm64-v8a/libps2EntryRunner.so` (107,386,928 bytes, SHA-256 `1DD555D4C5117C9C250248FEFAD3B701C3E0CAE55E96FF48B77551BB8496DBD2`, BuildID `6a70d3160a38acb6850b59a788bc19554992e4ce`, stored uncompressed because `useLegacyPackaging = false`) and `libsotc_core.so` for both ABIs. `app/build.gradle` uses `c++_static`, so `libc++_shared.so` is no longer packaged (D24). `verify-runner.sh` reports `RUNNER_VERIFY_OK (0 warnings)` on the new runner and `tools/android-integration/verify-apk.py` reports `APK_NATIVE_VERIFY_OK` with 0 failures and 0 warnings. Without the runner the APK is 6,237,436 bytes (SHA-256 `6018C6B3...EB46260`).
- GPU compatibility is real and verified on the only path available: the manifest floor is OpenGL ES 2.0, `EglRenderer` requests an ES 3 config/context and retries the whole sequence for ES 2 on any failure, shaders are GLSL ES 1.00 with vertex buffers instead of VAOs, `GLESv2` is linked, and Settings → Graphics offers `Force OpenGL ES 2.0`. On the API 28 emulator the ES 3 attempt failed and the ES 2 path rendered frames at 1280x720 (100% non-black screenshot, ~13-15 fps under SwiftShader). `engine/gpu_info.cpp` creates a short-lived offscreen context and reports backend/vendor/renderer/GLSL/limits; `engine/egl_display_lock.h` serializes display lifecycle between the render thread and that query. The detector now also collects EGL identity/extensions, extra GL limits, advertised timer/fence flags and shader/FBO/colour/depth/render-to-texture self-tests; `GpuInfo.Tier` is derived from those probes, never from a GPU vendor name (D25). Vulkan is not implemented.
- Installed application label is `SOTC`; application ID remains `com.portsotc.mobile`.
- Native libraries are aligned for 16 KB pages (`-Wl,-z,max-page-size=16384` in `app/src/main/cpp/CMakeLists.txt` and in the runner configure), so the app stays loadable on Android 15 devices with a 16 KB page-size kernel. `tools/android-integration/verify-runner.sh` checks the runner's ELF class, machine, entry point, touch symbols and STL dependency; `tools/android-integration/verify-apk.py` extends the 16 KB LOAD, ZIP and dependency checks to every packaged `.so` and reports `APK_NATIVE_VERIFY_OK`.
- Launcher is a product screen: status card, single primary Play action, details dialog, import/settings/controls actions. Play is disabled when the runtime is absent; when the disc tree is not prepared it opens Storage instead of starting a session. Diagnostics are reachable only from Settings -> Advanced.
- Disc-tree extraction is implemented and tested: `DiscTreeExtractor` extracts the whole ISO into `<files>/games/SCUS-97472/disc/`, publishes atomically, writes `disc_tree.properties` last, creates `mc0`, and is exposed as `PREPARE GAME DATA` / `RE-EXTRACT DISC DATA` in Settings -> Storage with progress and cancellation. 5 unit tests cover the paths.
- Gameplay host side is wired: `GameNativeActivity` (NativeActivity, `android.app.lib_name=ps2EntryRunner`) publishes `SOTC_BOOT_ELF`, the control knobs and `SOTC_AUDIO_VOLUME` through `NativeCore.setEnvironment` before `super.onCreate`, redirects the runtime's stdio to `<files>/logs/game-<yyyyMMdd-HHmmss>.log` (`nativeRedirectStdio`), and `core/RuntimeEnvironment.kt` owns the variable names and locale-independent formatting. Patches 0004/0005/0006 teach the runner to read them; patch 0009 adds the frame-limit/adaptive-scale environment inputs. The runner artifact exists and is packaged, but has never run on a device.
- `CoreProbe` detects native libraries both in the extracted `nativeLibraryDir` and inside the APK for the device's ABIs, covering uncompressed (`useLegacyPackaging=false`) packaging. `tools/android-integration/package-runner.sh` verifies (AArch64, `ANativeActivity_onCreate`) and copies the runner into `jniLibs/arm64-v8a` without committing it.
- Settings are categorized (General, Graphics, Performance, Audio, Controls, Storage, Advanced) with honest availability labels for unimplemented options.
- Touch controls support Classic/Modern/Compact/Custom presets, radial deadzone, camera sensitivity, axis inversion, input release on pause/focus loss, and automatic hiding when a gamepad is hot-plugged. The gameplay window has its own native overlay (patch 0005) that merges into the PS2 pad wire format; it compiles for ARM64 but has not run.
- Audio settings reach gameplay: the Audio category's toggle and master volume are published as `SOTC_AUDIO_VOLUME` and applied by patch 0006 right after the runtime loads its own settings, so mute works. The runtime's own menu can still change the volume for the current session. Not yet exercised on a device.
- Settings -> Advanced can read the runtime's log without a PC: `GameLogs` finds the newest `files/logs/game-*.log`, `VIEW LATEST GAME LOG` shows its tail in a selectable monospace dialog, and `COPY LATEST GAME LOG` puts it on the clipboard. 8 unit tests cover selection, tail truncation at a line boundary, and size formatting.
- Host foundation: EGL renderer, audio engine (AAudio/OpenSL), touch controls + gamepad input,
  ISO import + validation (ISO9660 / SYSTEM.CNF / PS2 ELF / XFF magic), diagnostics scene.

## What Does NOT Work Yet (honest status)

- **No game execution of any kind yet.** The ARM64 `libps2EntryRunner.so` is built, verified and packaged into the debug APK (`lib/arm64-v8a/`, 107,384,168 bytes), but no device or emulator has loaded it, so there is no boot, rendering, audio or input evidence from ARM64.
- M3 recompilation pipeline is **complete** (2026-11-18 20:34, `PIPELINE_DONE`); the x86_64 capture build produced `shots/run/frame_8.png`, the only rendering evidence so far.
- M4 is **build-complete** (2026-11-18 22:22): ARM64 runner linked and `RUNNER_VERIFY_OK`. It is not runtime-verified.
- M5 is partially done: the activity, boot-path and settings handoff, disc-tree extraction, launcher gating, and the runner-side touch overlay exist and are linked, but nothing has been booted on a device.
- No ARM64 hardware verification has happened (no device connected; B4). Emulators on this host cannot stand in: they are `x86_64` and cannot load an `arm64-v8a` library, the API 37 image needs 4 GB RAM against 3,791 MB of host RAM, and the API 28 image reports OpenGL ES 2.0 only.
- ES 3 rendering, the frame limiter and the thermal ceiling are not runtime-verified. The API 28 image rejects ES 3, SwiftShader cannot reach 30 fps so the cap never binds, and the emulator always reports thermal status 0.
- Patch 0009 (`SOTC_FRAME_LIMIT`, `SOTC_ADAPTIVE_RESOLUTION`, `[pace]`) is compiled into a rebuilt runner but has no device evidence; no `[pace]` line has been captured from a real session. The host engine's thermal ceiling still does not reach the runtime loop.
- The GPU self-tests use synthetic shaders and small render targets; they do not prove that the game's own shaders, formats or draw paths work. No full-game GPU compatibility claim is permitted.
